TP5 : Mini-projet d’analyse descriptive

knitr::opts_chunk$set(echo=FALSE, warning=FALSE, message=FALSE, eval=FALSE)

library(tidyverse)
library(here)

Ce TP est un mini-projet réalisé en classe, par groupes de deux ou trois. Chaque groupe choisit un jeu de données du projet TidyTuesday, se pose une question, y répond par une analyse descriptive et présente le résultat dans quelques slides réalisées avec Quarto.

Une analyse de données ne part pas des données, mais d’une question. Sans question, on accumule des tableaux et des graphiques qui ne disent rien ; avec une question, on sait quelles variables regarder, quels graphiques faire et quand s’arrêter. À chaque étape du TP, le groupe doit donc se demander : quelle question pose-t-on, les données permettent-elles d’y répondre, et que répond-on ?

Chaque membre du groupe crée un projet RStudio TP5 avec les sous-dossiers code, data et figures, et explore les données dans code/TP5.qmd. Les slides sont rédigées dans code/TP5_slides.qmd, sur un seul ordinateur.

Déroulé indicatif de la séance :

Étape Durée indicative
1. Choisir un jeu de données et une question 10 min
2. Décrire les données 30 min
3. Répondre à la question 50 min
4. Préparer les slides 20 min

1. Choisir un jeu de données et une question

TidyTuesday publie chaque semaine depuis 2018 un jeu de données réel, prêt à l’emploi. Chaque jeu de données a son propre dossier sur GitHub (par exemple data/2024/2024-05-21/), avec un fichier readme.md qui présente les données, donne le code R pour les importer (rubrique The Data) et décrit les variables (rubrique Data Dictionary). Le choix est libre ; quelques suggestions en lien avec l’économie, l’énergie ou l’environnement :

Jeu de données Contenu
Sustainable Energy for All Accès à l’électricité et part des renouvelables, par pays et par année
Global Health Spending Dépenses de santé de 195 pays depuis 2000
European Parenting Leave Policies Congés maternité et parentaux dans 21 pays européens, de 1970 à 2024
The Cappuccino Index Prix d’un cappuccino dans différents pays, en temps de travail d’un barista
Which College Majors Are Safest From AI? Salaire et exposition à l’IA des filières universitaires américaines
Carbon Majors Emissions Émissions des grands producteurs de pétrole, de gaz, de charbon et de ciment depuis 1854

Une bonne question est :

  • précise : elle porte sur une variable et une population bien identifiées ;
  • descriptive : elle demande « combien », « qui », « comment cela évolue » ou « en quoi deux groupes diffèrent », et non « quel est l’effet de… ? », question à laquelle une analyse descriptive ne permet pas de répondre ;
  • réalisable : les variables nécessaires sont dans le jeu de données ;
  • intéressante : on ne connaît pas la réponse à l’avance, et elle compte pour quelqu’un (un consommateur, une entreprise, un décideur public).
Question Diagnostic
Que disent les données sur les émissions de CO2 ? Trop vague
Les politiques climatiques ont-elles réduit les émissions ? Causale
Quels producteurs émettent le plus de CO2 : des entreprises privées, des entreprises publiques ou des États ? Bonne question

  1. Former un groupe de deux ou trois. Lire le readme.md de deux ou trois jeux de données qui intéressent le groupe, puis en choisir un.

  2. Avant d’ouvrir les données dans R, lister trois à cinq questions que ce jeu de données pourrait permettre de traiter.

  3. Retenir une question principale, et la découper en deux ou trois sous-questions. Pourquoi est-elle intéressante ? Quelles variables faut-il pour y répondre ? Quelle réponse attendez-vous ?

  4. Importer les données avec read_csv(), en copiant l’adresse donnée dans la rubrique The Data du readme.md, puis en enregistrer une copie dans le dossier data avec write_csv() et here().

2. Décrire les données

Avant de répondre à la question, il faut savoir ce que mesurent les données et vérifier qu’elles permettent d’y répondre.

  1. Qui a produit ces données, et comment ont-elles été collectées ? S’appuyer sur le readme.md et sur les liens qu’il donne.

  2. Afficher la structure du tableau avec glimpse(). Que représente une ligne ? Combien y a-t-il d’observations, sur quelle période et sur quel champ ?

  3. Construire le tableau de description des variables utiles à la question (nom, description en français, unité), au format Markdown.

  4. Compter les valeurs manquantes de chaque variable avec summarise() et across(), et repérer les anomalies (valeurs impossibles, unités différentes selon les lignes, lignes de total). Les données permettent-elles de répondre à la question ? Sinon, reformuler la question.

3. Répondre à la question

Chaque sous-question reçoit sa réponse sous la forme d’un tableau ou d’un graphique, choisi selon la nature des variables (TP3 et TP4) : distribution d’une variable, comparaison entre groupes, évolution dans le temps, relation entre deux variables.

  1. Pour chaque sous-question, produire le tableau ou le graphique qui y répond le plus directement. Les tableaux s’affichent avec knitr::kable().

  2. Soigner les graphiques : axes avec leurs unités, source des données (labs(caption = ...)), police lisible (theme_minimal(base_size = 16)).

  3. Écrire la réponse à chaque sous-question en une phrase, appuyée sur un chiffre. Le résultat correspond-il à ce que vous attendiez ?

  4. Quelles sont les limites des données pour répondre à la question ? Quelles nouvelles questions les résultats soulèvent-ils ?

4. Préparer les slides

Les slides suivent le plan de l’analyse, en trois parties :

  1. La question : la question principale, les sous-questions, et pourquoi elles sont intéressantes ;
  2. Les données : source, ce que représente une ligne, période, nombre d’observations, variables utilisées ;
  3. Les résultats : une slide par sous-question, avec un tableau ou un graphique, et un titre qui donne la réponse.

Quarto produit des slides au format HTML avec format: revealjs : chaque titre de niveau 2 (##) commence une nouvelle slide. Dans l’en-tête, echo: false masque le code de tous les chunks, et embed-resources: true produit un fichier HTML autonome. Modèle de document :

---
title: "La question principale"
author: "Prénom Nom, Prénom Nom, Prénom Nom"
format:
  revealjs:
    embed-resources: true
execute:
  echo: false
  warning: false
  message: false
---

```{r}
library(tidyverse)
library(here)

donnees <- read_csv(here("data", "nom_du_fichier.csv"))
```

## La question

- Question principale et sous-questions
- Pourquoi elles sont intéressantes

## Les données

- Source : ...
- Une ligne correspond à ...
- `r nrow(donnees)` observations, de ... à ...

## Un titre qui donne la réponse

```{r}
ggplot(donnees) +
  geom_col(aes(x = ..., y = ...)) +
  labs(x = "...", y = "...", caption = "Source : ...") +
  theme_minimal(base_size = 16)
```

  1. Créer le document code/TP5_slides.qmd à partir de ce modèle et le compiler. Ouvrir le fichier HTML produit dans un navigateur : les flèches du clavier permettent de passer d’une slide à l’autre.

  2. Rédiger cinq à sept slides en suivant le plan question, données, résultats. Le titre de chaque slide de résultat donne la réponse (« Dix producteurs émettent 60 % du total ») plutôt que le contenu (« Graphique 2 »).

  3. Relire les slides en se mettant à la place du public : la question est-elle claire ? Chaque résultat y répond-il ? Supprimer ce qui n’y répond pas.

5. Rendu

Compiler les slides. Le document doit se compiler sans erreur après un redémarrage de R (Session > Restart R). Un membre du groupe dépose le fichier TP5_slides.html sur CEL, après avoir indiqué le nom de tous les membres du groupe dans l’en-tête YAML (author).
