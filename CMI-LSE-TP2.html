TP2 : Manipuler des tableaux de données

knitr::opts_chunk$set(echo=FALSE, warning=FALSE, message=FALSE, eval=FALSE)

library(tidyverse)
library(here)
library(nycflights13)

Ce TP présente les principales opérations sur les tableaux de données avec les packages dplyr et tidyr du tidyverse : sélectionner, filtrer, trier, créer des variables, agréger, joindre et remodeler. On travaille d’abord sur les vols au départ de New York, puis sur les émissions de CO2 des pays du monde.

Comme au TP1, créer un projet RStudio TP2 avec les sous-dossiers code, data et figures, et rédiger les réponses dans le document code/TP2.qmd. Le chapitre sur dplyr du tutoriel de Julien Barnier est une bonne référence.

Les verbes de base de dplyr

Le package nycflights13 contient plusieurs tables sur les vols au départ des trois aéroports de New York en 2013.

Table / variable Description
flights Un vol par ligne
month, day Mois et jour du vol
dep_delay, arr_delay Retard au départ et à l’arrivée (en minutes)
carrier Code de la compagnie aérienne
origin, dest Codes des aéroports de départ et de destination
airports Un aéroport par ligne : code faa, nom name, altitude alt (en pieds), lat, lon, fuseau horaire tz et tzone
airlines Une compagnie par ligne : code carrier et nom name

Chaque verbe de dplyr prend un tableau en premier argument et renvoie un tableau. Le pipe %>% permet d’enchaîner les opérations : tableau %>% filter(...) %>% select(...) se lit « prendre le tableau, puis filtrer, puis sélectionner ».

  1. Afficher la structure de la table flights avec glimpse(). Combien compte-t-elle de lignes et de colonnes ? Que représente une ligne ?

  2. Avec filter(), sélectionner les vols du mois de juillet, puis les vols dont le retard à l’arrivée est compris entre 5 et 15 minutes, puis les vols des compagnies Delta, United et American (codes DL, UA et AA, utiliser %in%). Combien de vols obtient-on dans chaque cas ?

  3. Trier la table flights par retard au départ décroissant avec arrange() et desc(). Quel est le plus long retard ? Afficher l’aéroport situé à l’altitude la plus basse avec slice_min().

  4. Dans la table airports, sélectionner avec select() les colonnes name, lat et lon, puis toutes les colonnes sauf tz et tzone. Dans flights, sélectionner les colonnes dont le nom se termine par delay (ends_with()). Renommer enfin la colonne alt de airports en altitude avec rename().

  5. Avec mutate(), créer dans airports une variable alt_m donnant l’altitude en mètres (1 mètre = 3.2808 pieds), puis ne conserver que name, alt et alt_m. Écrire ces opérations avec le pipe.

  6. En une seule chaîne d’opérations : sélectionner les vols de septembre et d’octobre, conserver les colonnes dest et dep_delay, créer une variable retard_h donnant le retard au départ en heures, et afficher les 5 vols les plus retardés avec slice_max().

Importer et explorer des données

On utilise la base de données sur les émissions de CO2 de Our World in Data, qui couvre tous les pays depuis 1750. Les variables utilisées sont les suivantes :

Variable Description
country Pays ou agrégat régional
year Année
iso_code Code ISO du pays à 3 lettres (vide pour les agrégats régionaux)
population Population
gdp PIB, en dollars internationaux de 2011 (parité de pouvoir d’achat)
co2 Émissions annuelles de CO2, hors changement d’usage des sols (en millions de tonnes)
co2_per_capita Émissions de CO2 par habitant (en tonnes)
  1. Dans la console, télécharger le fichier dans le dossier data avec download.file() :
download.file("https://raw.githubusercontent.com/owid/co2-data/master/owid-co2-data.csv",
              here("data", "owid-co2-data.csv"))

Dans le document, importer ensuite le fichier avec read_csv() et here() dans un objet co2. Pourquoi télécharger le fichier une fois plutôt que lire directement l’URL à chaque compilation ?

  1. Afficher les dimensions de co2 et sa structure. Que représente une ligne du tableau ?

  2. Quelle période couvrent les données ? Combien de pays ou régions distincts contiennent-elles (utiliser n_distinct()) ?

  3. Afficher la liste des entités dont le code ISO est manquant (is.na(), puis distinct()). De quoi s’agit-il ? Pourquoi faut-il les retirer avant de calculer des totaux ?

  4. Créer un tableau co2_pays qui ne contient que les pays (code ISO renseigné), à partir de 1990, et les seules variables du tableau ci-dessus. Afficher un résumé du tableau avec summary(), puis les données de la France de 2020 à 2024. Que remarquez-vous pour la variable gdp ?

  5. Enregistrer co2_pays dans le dossier data avec write_csv(), sous un nom différent du fichier d’origine.

Agréger des données

Pour résumer un tableau par groupe, on combine group_by(), qui définit les groupes, et summarise(), qui calcule une statistique par groupe. La fonction count() compte le nombre de lignes par groupe.

  1. Compter le nombre de vols par mois avec count(), puis trier le résultat par nombre de vols croissant. Quel est le mois le plus chargé ?

  2. Calculer, pour chaque aéroport de départ (origin), le retard moyen au départ et le nombre de vols (n()). Pourquoi faut-il utiliser l’argument na.rm = TRUE ?

  3. Pour chaque mois, afficher la destination qui compte le plus de vols. Utiliser count(), group_by() et slice_max().

  4. À partir de co2_pays, calculer les émissions mondiales de CO2 pour chaque année. Comparer la valeur de 2023 avec celle de la ligne World du tableau co2. D’où peut venir l’écart ?

  5. Pour l’année 2023, calculer la part de chaque pays dans les émissions mondiales, puis afficher les 10 plus gros émetteurs avec leurs émissions totales, leurs émissions par habitant et leur part. Commenter.

  6. Pour la France, l’Allemagne, les États-Unis, la Chine et l’Inde, créer une variable decennie (utiliser la division entière %/%) et calculer les émissions moyennes par habitant par décennie. Commenter les évolutions.

Joindre et remodeler des tableaux

Une jointure associe les lignes de deux tableaux à partir d’une variable commune, appelée clé. left_join(x, y) conserve toutes les lignes de x et leur ajoute les colonnes de y ; anti_join(x, y) renvoie les lignes de x sans correspondance dans y.

Un tableau est au format long lorsque chaque ligne est une observation (un pays une année), et au format large lorsque les modalités d’une variable sont en colonnes (une colonne par année). On passe de l’un à l’autre avec pivot_wider() et pivot_longer().

  1. Joindre la table airlines à la table flights avec left_join(). Calculer ensuite le retard moyen au départ pour chaque compagnie, en utilisant son nom, et trier par retard décroissant.

  2. Joindre la table airports à la table flights en utilisant comme clé le code de l’aéroport de destination (by = c("dest" = "faa")). Quelles sont les trois destinations les plus fréquentes ? Avec anti_join(), identifier les destinations absentes de la table airports.

  3. Importer la classification des pays par continent de Our World in Data, en la téléchargeant d’abord dans data comme à la partie précédente :

download.file("https://ourworldindata.org/grapher/continents-according-to-our-world-in-data.csv?v=1&csvType=full&useColumnShortNames=true",
              here("data", "continents.csv"))

Joindre la variable owid_region, renommée continent, au tableau co2_pays : la clé est iso_code d’un côté et code de l’autre. Quels pays n’ont pas de continent ?

  1. Calculer les émissions totales de chaque continent en 1990 et en 2023, puis passer au format large avec pivot_wider() (une colonne par année). Ajouter une variable donnant l’évolution en pourcentage entre les deux années. Commenter.

  2. Revenir au format long à partir du tableau précédent avec pivot_longer(). Pourquoi le format long est-il le plus adapté pour faire des calculs par groupe ou des graphiques ?

  3. Enregistrer le tableau co2_pays complété des continents dans data/co2_continents.csv. Il sera réutilisé au TP3.
